# 문체 교정과 자동 점검

제출용 산출물을 저장하기 전에 읽는다. 사실, 공개 범위, 저장 기준은 `../SKILL.md`를 따른다.
사용자에게 따로 묻지 않고 매번 자동으로 실행한다.

## 실행 순서

1. **사실 확정:** 초안의 역할, 기간, 수치, 기술명을 근거와 대조한 상태에서 시작한다.
2. **반복 1차 교정:** 아래 반복과 동의어 기준으로 직접 고친다.
3. **윤문:** 산문형 본문(자기소개서, 경력기술서와 포트폴리오의 서술 문단)에 humanize-korean을
   적용한다. 개조식 이력서 항목과 표에는 적용하지 않는다.
4. **윤문 후 대조:** 윤문 전후를 비교해 수치, 기간, 고유명사, 기술명, 역할 동사(`주도`, `참여`,
   `지원` 등), 문항 제목이 그대로인지 확인한다. 바뀌었으면 해당 문장만 되돌린다.
5. **자동 점검:** `scripts/check_text.py`를 실행한다. 차단 항목이 0건이 될 때까지 고치고 다시
   실행한다. 세 번 고쳐도 남으면 멈추고 남은 항목을 보고한다.
6. **재검토 항목 처리:** 고치거나, 유지할 이유를 검토 메모에 한 줄로 남긴다.
7. **보고:** 최종 분량은 스크립트 출력값을 그대로 쓴다. 눈대중으로 센 값을 쓰지 않는다.

## humanize-korean 연계

사용 가능한 스킬 목록에 humanize-korean 플러그인(Claude Code의 `humanize-korean:*`, Codex의
`$humanize-korean`)이 보이면 자동으로 쓴다. 플러그인 구성과 쓰임은 다음과 같다.

| 스킬 | 이 스킬에서의 쓰임 |
|---|---|
| `humanize-scan` | 먼저 실행해 AI 티 신호 수를 본다. 발동 신호가 3개 미만이고 수정 전문을 받았다면 그 결과를 쓰고 윤문 단계를 마친다. |
| `humanize-korean` | 신호가 3개 이상이거나 새로 쓴 자기소개서일 때 전체 윤문을 실행한다. 장르는 `공적`(essay), 강도는 `기본`이다. 근거가 빠듯한 문장이 많으면 `보수`로 낮춘다. |
| 2차 윤문 | 등급이 B 이하로 나오면 `humanize-korean`에 같은 실행의 "2차 윤문"을 한 번 더 요청한다. 그래도 C 이하면 멈추고 보고한다. |
| `/humanize`, `/humanize-redo` | 사용자가 직접 입력하는 명령이라 모델이 대신 실행할 수 없다. 내용은 위 두 줄과 같은 파이프라인이므로 따로 부르지 않고, 사용자가 직접 돌려 보고 싶어 할 때만 안내한다. |

- 입력은 답변 본문만 넘긴다. 문항 질문, 검토 메모, 메타정보는 빼고 `## 문항 1`처럼 짧은 제목으로
  구분한다. 문항이 여러 개여도 한 번에 넘겨 실행 횟수를 줄인다.
- humanize-korean은 현재 작업 폴더에 `_workspace/`를 만들고 원문과 윤문본을 남긴다. 결과 보고에
  그 위치를 알리고, 지우거나 다른 곳으로 옮기지 않는다.
- 우선순위: 사실, 수치, 책임 범위, 분량 제한은 이 스킬의 기준이 앞선다. 윤문이 문장을 이어
  분량을 넘기면 사실이 아닌 군더더기부터 줄인다. 존댓말 종결(`~습니다`)과 문체는 원문을 따른다.
- 설치되어 있지 않으면 설치를 요구하지 않는다. 아래 내장 점검으로 진행하고 결과에
  "humanize-korean 미설치, 내장 점검만 수행"과 설치 방법 한 줄을 적는다.

## 가운뎃점 제거

- 제출용 산출물, 검토 메모, 분석 보고서, 파일명에 가운뎃점 계열 문자를 하나도 남기지 않는다.
  대상은 U+00B7, U+318D, U+30FB, U+2027, U+2219, U+FF65, U+22C5이며 스크립트가 모두 잡는다.
- 바꾸는 법: 셋 이상 나열은 쉼표(`기획, 개발, 운영`), 두 항목의 결합은 조사(`기획과 개발`),
  선택은 `또는`, 관용 표기는 그 표기(`A/B 테스트`)로 쓴다. 문맥 없이 일괄 치환하지 않는다.
- 공식 명칭에 들어 있어도 제출본에서는 띄어 쓰고, 원래 표기는 검토 메모에 남긴다.
- 사용자 원본과 공고 원문 파일은 고치지 않는다. 인용해 옮겨 적을 때만 바꾼다.
- 글머리표 `•`는 가운뎃점이 아니지만 Markdown 산출물에서는 `-` 목록으로 통일한다.

## 반복과 동의어

문항 질문과 메타정보를 뺀 답변 본문을 문항별로 본다. 스크립트가 후보를 찾고, 판단은 읽고 한다.

- **핵심어:** 같은 핵심어가 한 문항에 5회 이상이면 반드시 재검토한다. 3회부터는 참고로 표시된다.
  상한이 아니라 검토 신호다. 영문 대소문자와 조사 부착은 같은 말로 센다(`AI`, `ai`, `AI를`).
  다른 영단어 안의 `ai`는 세지 않는다.
- **인접 반복:** 횟수가 적어도 이웃한 두 문장에 같은 핵심어가 반복되면 하나를 줄일 수 있는지 본다.
- **동의어:** `AI`를 `인공지능`으로, `개선`을 `향상`으로 바꿔 반복을 감춘 것은 해결이 아니다.
  같은 뜻의 말이 한 문항에 합쳐 3회 이상이면 문장 구조로 줄인다.
- **구절:** `~을 통해`, `~할 수 있었습니다`, `~게 되었습니다`, `~라고 생각합니다`, `A가 아니라 B`는
  한 문항에 2회부터 재검토한다. 같은 어절 세 개가 연속으로 두 번 나와도 재검토한다.
- **문장:** 같은 문장은 문항 사이에서도 차단이다. 비슷한 문장(글자쌍 유사도 0.6 이상)은 재검토한다.
  독립된 답변에 필요한 기술명이 다시 나오는 것은 허용한다.

교정 순서: 중복 문장 삭제와 통합 → 불필요한 수식어와 주어 생략 → 확인된 행동과 대상으로
구체화 → 의미가 정확한 다른 표현. 원본에 없는 구현 방식이나 성과를 넣지 않는다.
대상 구분이나 정확성 때문에 반복을 남길 때는 검토 메모에 이유를 적는다. 기술명이라는
이유만으로 일괄 제외하지 않는다. 교정 뒤 의미, 필수 기술명, 질문에 대한 답을 다시 확인한다.

## 내장 문체 점검

humanize-korean이 없을 때 직접 확인하는 신호다. 스크립트가 일부를 참고 항목으로 보여 준다.
신호 선정은 humanize-korean(im-not-ai, MIT)의 실측 결과를 참고했다.

| 신호 | 고치는 법 |
|---|---|
| `A가 아니라 B` 대구가 2회 이상 | 가장 필요한 1회만 두고 나머지는 바로 말한다. |
| 문장 길이가 고르고 긴 문장이 거의 없음 | 이어도 되는 두 문장을 잇고 짧은 문장을 섞는다. 내용은 더하지 않는다. |
| 연결어미 뒤 쉼표(`개선했고,`) | 쉼표를 뺀다. |
| 같은 종결이 4문장 이상 연속(`~했습니다`) | 종결만 바꾼다(`~했고`, `~였습니다`). 시제와 서법은 그대로 둔다. |
| `~적 명사` 추상 표현이 3회 이상 | 구체적인 대상이나 행동으로 풀어 쓴다. |
| 상투 표현(`어릴 때부터`, `누구보다`, `귀사`, `밑거름`) | 회사명과 실제 경험으로 바꾼다. |

맞춤법, 띄어쓰기, 오탈자는 스크립트가 보지 않으므로 직접 읽고 고친다. 150자가 넘는 문장은 두
가지 이상의 행동이나 결과가 섞여 한 번에 읽히지 않을 때만 나눈다.

## 스크립트

```sh
python3 scripts/check_text.py <파일> [--limit 700,1000] [--unit chars|nospace|utf8|cp949] \
  [--forbid "다른회사,이전 지원 회사"] [--ref 합격자소서1.md 합격자소서2.md] [--json]
```

- Claude Code에서는 `${CLAUDE_SKILL_DIR}/scripts/check_text.py`로 부른다. Python 3.8 이상,
  표준 라이브러리만 쓴다. Python이 없으면 위 기준으로 직접 점검하고 "자동 점검 미실행"을 보고한다.
- 입력 파일은 문항 질문을 Markdown 제목(`##`)으로, 답변은 그 아래 일반 문장으로 둔다. 제목 줄은
  분량과 반복 집계에서 빠진다. 검토 메모는 별도 파일이므로 섞이지 않는다.
- `--limit`는 문항 순서대로 적용한다. 값이 하나면 모든 문항에 같은 제한을 건다.
  `--unit`의 `chars`는 공백과 줄바꿈 포함, `nospace`는 공백 제외, `utf8`과 `cp949`는 바이트다.
  국내 채용 사이트의 바이트 제한은 보통 한글 2바이트(`cp949`)지만 사이트마다 다르고,
  줄바꿈을 2자로 세는 곳도 있으므로 확인하지 못한 방식은 미검증으로 보고한다.
- `--forbid`에는 이전에 지원한 회사명 등 남으면 안 되는 문자열을 넣는다.
  `--ref`에는 합격 자기소개서처럼 문장을 가져오면 안 되는 자료를 넣는다.
- 등급: **차단**(가운뎃점, 자리표시자, 금지 문자열, 분량 초과, 같은 문장, 참고 자료와 5어절 이상
  일치)은 반드시 고친다. **재검토**는 고치거나 유지 이유를 남긴다. **참고**는 읽고 판단한다.
- 형태소 분석기가 아니므로 오탐과 누락이 있다. 결과를 근거로 의미를 바꾸지 않는다.
