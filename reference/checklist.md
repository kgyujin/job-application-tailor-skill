# 최종 검수

모드 A 저장 전에, 모드 D, E, F 보고서 저장 전에 읽는다. 요청한 산출물에 해당하는 항목만 확인한다.
작성, 저장 기준은 `../SKILL.md`, 문체와 자동 점검 기준은 `style-guide.md`를 따른다.
해당 없는 항목은 실패로 처리하지 않으며, 미확인을 통과로 보고하지 않는다.

## 공고와 근거

- [ ] 필수 조건, 우대사항, 주요 업무를 구분하고 복합 조건의 의미를 보존했는가
- [ ] 회사명, 직무명, 기술명, 제출 제약을 원문에 대조했는가
- [ ] 문화와 가치관 키워드는 공고와 기업 분석에서 실제 확인된 범위만 썼는가
- [ ] 충족 요건은 근거로 드러나고 부분 충족, 미충족, 미확인은 구분해 보고했는가
- [ ] 역할, 기간, 수치를 원본이나 사용자 확인과 연결하고 충돌한 사실을 임의로 합치지 않았는가

## 이력서

- [ ] 관련 경험을 앞에 배치하고 확인된 수치, 기술, 역할을 유지했는가
- [ ] 실제로 보존하거나 검증한 범위만 형식과 양식 유지로 보고했는가

## 자기소개서

- [ ] 문항의 하위 질문에 모두 답하고 첫 문장이 핵심 답을 전달하는가
- [ ] 질문과 분량에 맞는 경험과 구조를 고르고 문항 사이에 소재가 겹치지 않는가
- [ ] 본인의 수행과 판단 범위를 팀 성과와 구분했는가
- [ ] 강화한 표현이 확인된 사실과 책임, 숙련도 범위를 벗어나지 않는가
- [ ] 비유를 썼다면 첫 문장부터 답을 전달하고 실제 경험으로 증명되는가
- [ ] 합격 자기소개서를 참고했다면 패턴만 썼고 `--ref` 점검에서 일치가 0건인가

## 문체와 자동 점검

- [ ] humanize-korean을 실행했거나, 미설치라 내장 점검으로 대신했다고 기록했는가
- [ ] 윤문 뒤 수치, 기간, 고유명사, 기술명, 역할 동사, 문항 제목이 바뀌지 않았는가
- [ ] `check_text.py`의 차단 항목이 0건인가(가운뎃점, 자리표시자, 다른 회사명, 분량 초과, 같은 문장, 참고 자료 일치)
- [ ] 재검토 항목(5회 이상 핵심어, 동의어 반복, 반복 구절, 비슷한 문장)을 고치거나 유지 이유를 남겼는가
- [ ] 동의어 치환으로 반복을 감추거나 기술 의미를 바꾸지 않았는가
- [ ] 같은 지원 건의 산출물을 한 번에 넘겨 용어 통일을 검사했고, 공고 표기와 다른 표기와 영문 표기 혼용이 0건인가
- [ ] 띄어쓰기, 한글과 영문, 약어, 외래어 표기 혼용을 통일했거나 남긴 이유를 용어 기준표에 적었는가
- [ ] 맞춤법, 띄어쓰기, 오탈자를 직접 읽어 확인했는가
- [ ] 최종 분량을 스크립트 값으로 보고하고 계산 기준과 미검증 범위를 기록했는가

## 페르소나 검토

- [ ] 산출물 규모에 맞는 페르소나 검토를 수행하고 지적과 조치를 검토 메모에 남겼는가
- [ ] 새 사실이 필요한 제안은 고치지 않고 사용자 질문으로 돌렸는가

## 분석 보고서

- [ ] 외부 사실마다 출처, 확인일, 신뢰도가 붙어 있고 `추정`을 사실처럼 쓰지 않았는가
- [ ] 동명 회사, 모회사, 자회사, 계열사를 섞지 않았는가
- [ ] 합격자 분석의 표본 수, 연도, 한계를 밝히고 개인 식별 정보를 남기지 않았는가
- [ ] 사용자 경험이 없는 서류 연결 포인트를 만들지 않았는가

## 포트폴리오와 저장

- [ ] 프로젝트 우선순위와 기술적 판단, 성과가 공고와 연결되는가
- [ ] 원본과 이전 산출물을 보존하고 요청한 결과를 새 버전으로 저장했는가
- [ ] 제출 본문과 근거, 확인 질문, 검토 메모를 분리했는가
- [ ] 미확인 사실이 필요한 결과는 초안으로 표시하고 최종본으로 보고하지 않았는가
- [ ] 변경 파일, 핵심 변경 내용, 남은 미확인과 미검증 사항을 보고했는가
