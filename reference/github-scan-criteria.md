# GitHub 프로젝트 자동 정리 (모드 C) 상세 기준

SKILL.md G1~G6단계 요약의 확장판. 명령어를 정확히 확인하고 싶을 때, 레포 포함/제외
경계 사례를 판단할 때, md 필드 매핑을 확인할 때 이 문서를 참조한다.

## 0. 사전 조건

- `gh` CLI 설치 여부: `gh --version` (미설치 시 https://cli.github.com 안내)
- 인증 여부: `gh auth status`
- Private 레포 접근에는 `repo` 스코프가 필요하다. `gh auth status`에 스코프가
  표시되지 않거나 `repo`가 없으면 private 스캔을 진행하지 말고 사용자에게 알린다.
- 토큰을 파일이나 코드에 직접 적지 않는다. 항상 `gh` 로컬 인증 세션을 통해서만
  API를 호출한다.

## 1. 레포 목록 수집 명령

```sh
gh repo list {대상계정} \
  --visibility {public|private|all} \
  --limit 300 \
  --json name,description,isPrivate,isFork,isArchived,pushedAt,createdAt,primaryLanguage,stargazerCount,url
```

- `{대상계정}`을 생략하면 `gh repo list`는 인증된 계정 기준으로 동작한다. 명시적으로
  다른 사용자를 스캔하려면 계정명을 지정한다(단, 그 경우 private 레포는 접근 권한이
  없으면 조회되지 않는다 — 정상 동작이며 오류로 취급하지 않는다).
- 레포가 300개를 초과하는 계정은 `--limit`을 늘리기보다 최근 활동일(`pushedAt`) 기준
  상위 N개로 먼저 좁히고, 사용자에게 전체 스캔이 필요한지 확인한다(API 호출량 관리).

## 2. 1차 제외 판단 기준 (G3단계)

아래 조건에 해당하면 "제외 후보"로 표시한다. 완전히 목록에서 지우지 않고 G5단계
요약표에 사유와 함께 남겨 사용자가 최종 판단하게 한다.

| 조건 | 판단 |
|---|---|
| `isFork: true`이고 원본 대비 추가 커밋이 없음 | 제외 후보 (단순 포크) |
| `isArchived: true`이고 최근 2년 이상 활동 없음 | 제외 후보 (사용 중단) |
| 커밋 수가 매우 적음(대략 3커밋 미만) | 제외 후보 (실험용/빈 레포 가능성) |
| README가 없고 커밋 메시지도 의미를 파악하기 어려움 | 제외 후보 — 단, 사용자가 "이건 중요한 프로젝트"라고 지목하면 포함 |
| dotfiles, 개인 설정, 튜토리얼 그대로 따라한 레포로 보임 | 제외 후보 — 사용자에게 확인 |
| fork이지만 원본 대비 의미 있는 추가 커밋이 있음 | 포함 후보 (본인 기여분 중심으로 설명) |

이 기준은 참고용 휴리스틱이다. 사용자가 특정 레포를 반드시 포함해달라고 요청하면
그 요청을 따르되, 심화 조사(G4)에서 나온 사실(기여 비중, 커밋 수 등)은 그대로 함께
보고한다.

## 3. 심화 조사 명령 (G4단계)

```sh
# README (base64 디코딩 필요)
gh api repos/{owner}/{repo}/readme --jq .content | base64 -d

# 언어 비중 (바이트 수 기준)
gh api repos/{owner}/{repo}/languages

# 컨트리뷰터별 기여 통계 (본인 기여 비중 계산용)
gh api repos/{owner}/{repo}/stats/contributors
```

- `stats/contributors`는 통계 생성에 시간이 걸릴 수 있어(202 응답) 첫 호출에서
  비어 있으면 잠시 후 재시도한다. 반복 재시도 횟수는 최대 2~3회로 제한한다(무제한
  재시도 금지).
- 컨트리뷰터가 1명(본인)뿐이면 "개인 프로젝트"로 표시한다.
- 컨트리뷰터가 2명 이상이면 본인 커밋 수 / 전체 커밋 수 비율을 계산해 기여 비중으로
  표시한다. 비중이 낮아도(예: 20% 미만) 제외하지 않고 "기여 비중 낮음 — 실제 담당
  범위 확인 필요"로 표시해 사용자가 직접 설명을 보완하게 한다.

## 4. md 필드 매핑 (G6단계)

`resume-markdown-editor` 계약(README.md 참조: `document`, `##` 섹션, `###` 항목,
`기간`/`설명`/`기술`/`링크`/`성과` 필드)에 맞춰 다음과 같이 매핑한다.

| md 필드 | 데이터 출처 |
|---|---|
| `### {항목명}` | 레포 이름(또는 README 제목이 더 명확하면 그것을 사용하고 원 레포명을 링크로 남김) |
| `기간` | `createdAt` ~ `pushedAt` (연-월 단위로 축약) |
| `설명` | README 요약. 과장 없이 README/커밋 메시지에 있는 사실만 재서술한다 |
| `기술` | `languages` API 결과 중 비중 상위 언어(대략 5% 미만 언어는 생략 가능) |
| `링크` | 레포 URL. private 레포는 사용자가 공개 동의한 경우에만 링크를 남기고, 아니면 링크를 비운다 |
| `성과` | README/릴리스 노트/커밋 메시지에 정량적 근거가 명시된 경우에만 기입. 없으면 `- (본인 확인 필요)`로 남긴다 |

`## 기술 스택` 섹션은 전체 후보 레포의 언어 비중을 합산해 상위 언어 목록으로
작성한다. `resume-markdown-editor`처럼 `### Core` / `### Platform` 그룹으로 나누고
싶다면, 그 구분 근거(예: 주 언어 vs 인프라/툴)를 사용자에게 확인한 뒤에만 나눈다 —
임의로 그럴듯한 그룹명을 지어내지 않는다.

## 5. Private 레포 처리 시 주의사항

- private 레포는 회사/팀 소유이거나 재직 중 작성한 코드일 수 있다. 포함하기 전에
  반드시 "회사 소유 코드인지, 공개해도 되는 내용인지" 확인 질문을 한다.
- 확인되지 않은 private 레포는 md 초안에 이름과 기간만 남기고 설명/기술 상세나
  링크는 비워둔 채 "공개 가능 여부 확인 후 채워달라"고 표시한다.
- private 레포의 실제 코드/README 원문을 스킬 저장소나 대화 로그 이외의 외부
  서비스로 전송하지 않는다.

## 6. 배포 환경 호환성 메모

이 스킬은 공개 저장소로 배포되어 다른 사용자도 자신의 계정에 그대로 사용한다.
다음을 항상 지킨다.

- 사용자마다 `gh` 설치/인증 상태가 다르므로 G1단계 점검을 생략하지 않는다.
- 특정 GitHub 사용자명이나 조직명을 코드/문서에 하드코딩하지 않는다.
- API 호출 실패(권한 없음, rate limit 등)는 조용히 무시하지 말고 사용자에게 어떤
  레포/호출이 실패했는지 알린다.
